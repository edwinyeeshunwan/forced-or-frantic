# Replication — "Forced or Frantic?"

This bundle reproduces every number, table, and figure in *Forced or Frantic? Deleveraging
Cascades and Price Dislocation on a Transparent Perpetual-Futures Venue* (Edwin Wan).

The entire study uses **free data**. The only cost is small AWS data-transfer on
requester-pays S3 buckets (cents). Nothing here depends on a proprietary feed.

---

## 2. Requirements

- Python 3.10+ with: `pandas numpy matplotlib boto3 lz4 pyarrow duckdb`
  ```
  pip install pandas numpy matplotlib boto3 lz4 pyarrow duckdb --break-system-packages
  ```
- An **AWS account** with credentials configured (`aws configure`), for the two requester-pays
  S3 archives. Setup details and cost notes are in **README_phase2_freepath.md**.
- No statistical libraries beyond numpy are needed: permutation tests, Kaplan–Meier, the log-rank
  test, and the chi-square p-value are implemented from scratch (the chi-square survival function
  uses `math.erfc`), so results do not depend on a particular SciPy/lifelines version.

## 3. Run order

Run from inside `scripts/`. Each step writes to `../data/` (or `../figures/`, `../`).

| # | Command | Produces | Maps to |
|---|---------|----------|---------|
| 1 | `python3 pull_hl_asset_ctxs.py --start 2025-07-01` | `hyperliquid_{BTC,ETH}_{oi,klines,funding}` | open interest, price, funding |
| 2 | `python3 pull_hl_reservoir.py` | `hyperliquid_{BTC,ETH}_{liquidations,adl}` | liquidation trigger + ADL check |
| 3 | `python3 build_event_table_liq.py` | `event_table_liq`, `events_liq_*` | the 162-event sample |
| 4 | `python3 analyze_liq_events.py` | `H2_H3_results.md`, `figures/km_recovery_by_class.png` | **Table 1, Figure 1** |
| 5 | `python3 robustness_liq.py` | `robustness_results.md` | **Tables 2 and 3** |
| 6 | `python3 strengthen_liq.py` | `strengthening_results.md` | **Table 4**, §6 validation + continuous-measure + economic-significance numbers |

Steps 1–2 are network pulls (a few minutes each; requester-pays). Steps 3–6 are local computation
on the pulled data and take seconds. Always run each puller's `--inspect` mode first (it downloads
one file and prints the schema) before a full pull — see README_phase2_freepath.md.

## 4. Where each paper result comes from

- **Table 1** (group medians) and **Figure 1** (Kaplan–Meier recovery curves): `analyze_liq_events.py`.
- **Table 2** (magnitude-controlled OLS) and **Table 3** (robustness grid): `robustness_liq.py`.
- **Table 4** (event-window sensitivity), the **classification validation** (liquidation-notional,
  Spearman, ADL, funding swing, post-event volatility), the **continuous-ΔOI** regressions, and the
  **economic-significance** figures: `strengthen_liq.py`.
- The **headline permutation / log-rank tests** (H2a, H2b, H3): `analyze_liq_events.py`.

All thresholds, windows, the ΔOI class cuts, the merge rule, the recovery tolerance, and the
robustness grid are fixed in **00_Design_Spec.md**, which was frozen before estimation.

## 5. Notes and honest caveats (as stated in the paper)

- **Single venue.** Hyperliquid is chosen for its complete, public liquidation record; external
  validity to centralized exchanges is not established here.
- **Window.** The binding constraint is liquidation coverage (Reservoir begins ~Aug 2025), so the
  event sample runs 10 Aug – 31 Dec 2025. To extend back into 2024, parse Hyperliquid's raw node
  fills — see the "free upgrade" section of README_phase2_freepath.md.
- **Price.** A 1-minute mid resampled to 5-minute OHLC; intrabar extremes are slightly understated,
  which biases dislocations toward zero (conservative).
- **Schemas can drift.** Both archives may change layout; the `--inspect` modes and the
  `*_CANDIDATES` lists in the pullers are how the pipeline stays robust to that.
